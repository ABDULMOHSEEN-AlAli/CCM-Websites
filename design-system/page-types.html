Page types

Most pages on the five websites are one of a few kinds. We design each kind once, agree on it, and then use the same design on every page of that kind, on every site. That keeps the sites consistent and saves designing page by page.

    How we agree on a design

    The same seven steps for every page type. A design is only used on real pages after step 5.

    1. Pick a sample page

      Claude takes one real page of the type from the department we're working on, with its real content.

      Claude
    2. Two or three options

      Built with the same content, colours and fonts; only the layout changes. A compare page shows each one on desktop and phone, with "Good for" and "Watch out".

      Claude
    3. Review

      On the compare page, mark each option First choice, Could work or No, and write what you like or want changed. Mixing is fine. Click Copy feedback and send it to Claude. Teammates can do the same and send you the file.

      You and your team
    4. One combined design

      Claude turns the feedback into one design. Steps 3 and 4 repeat until you're happy; we aim for two rounds at most.

      Claude
    5. Approve

      You say "approved". It goes into the decisions list below with the date. The design becomes the standard: its parts move into the design system, and the options that weren't chosen are deleted.

      You
    6. Test in Sitefinity

      One page of the type on a hidden draft page: Preview and Save as draft only.

      You
    7. Use it everywhere

      Every page of the type on the current department's site. Each one passes check-page.mjs and the page checklist before upload.

      Both

    How to judge an option

    • Does it follow the KFUPM brand rules?
    • Can a visitor find what they came for quickly?
    • Does it work on a phone?
    • Can an editor keep it up to date in the CMS?
    • Does it work for little content and for a lot?

    What doesn't get re-opened

    • Colours, fonts, type sizes and spacing: they're set in the design guide.
    • The header, footer and side menu: they stay as they are for now.
    • An approved design. To change it, we change it in the design system, so every page changes together, and we note why in the decisions list.

    All types, in the order we work on them

    Page counts come from each site's menu (18 November 2026). Pages like "News article" stand for many pages built from one design. The types were chosen from page titles; a page can move to another type once we open it.

    Why this order. People list is already under way. The text page comes next because it is the biggest group and it builds the parts every other type reuses: text, notice boxes, link cards, download lists and questions that open and close. Types that read from Sitefinity's own lists (profiles, news, events) and the home pages wait for template access, though we can design them earlier.

    Built with. Content block We can build and upload these now, as HTML + CSS. Widget template These show items from Sitefinity's own lists (People, News, Events), so they go live once we have template access. Page template Needs page-layout access.
